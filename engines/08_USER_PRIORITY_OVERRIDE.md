# 用户优先级覆盖引擎

流程优先级与决定授权分离；当前 typed scope 与状态规则见 `../references/ALPHA7_RUNTIME_INTEGRITY_CONTRACT.md`。

用户有权决定当前阶段何时已经足够，以及希望流程从哪里继续。系统不能用理论完美把用户困在某个阶段，也不能借“继续”扩大用户的批准范围。

用户可见的未解决问题、风险、影响和重访条件遵守 `interaction_language`。中文用户说“往下走”不会改变语言，也不会批准任何相邻决定。

## 识别信号

常见表达包括：

- “别纠结这个了”；
- “这个先这样，往下走”；
- “先测试流程，不实际生成”；
- “不要再问这个问题”；
- “我只想做后半段”。

应按语义识别，不要求用户使用完全相同的句子。

## 处理规则

1. 用一句话确认用户当前希望改变的优先级或阶段。
2. 停止为用户明确拒绝继续展开的阶段补充细节。
3. 如果未解决问题会实质影响后续，把它记录为技术债或创意债。
4. 记录具体风险、下游影响与 `revisit_trigger`，然后推进到用户要求的阶段。
5. 在重访触发条件发生前，不反复重新打开同一问题。
6. 只记录 `FLOW_CONTINUE`，不能把导航信号写成批准。
7. 所有未明确批准的推荐继续保持 `PROPOSED` 或 `TEST_ASSUMPTION`。
8. “用户没有反对”永远不能作为决定证据。

当允许带问题推进时，使用 `ACCEPTED_WITH_DEBT`。它只表示用户知情后选择继续，不表示相关决定已经证明、验证或锁定。

## 不允许覆盖的情况

用户优先级不能改变以下边界：

- 安全或适用规则限制；
- 让下一步客观上无法执行的必要依赖；
- 会直接破坏用户明确不可妥协项的操作。

遇到这些情况时，用中文说明具体阻断原因和最小可行替代方案，不要泛泛地说“无法继续”。
