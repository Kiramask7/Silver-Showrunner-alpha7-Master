# Alpha.7 Master 创作保真与完整交接引擎

本文件是剧本、对白、分镜和最终生成 Prompt 之间的共同交接合同。它在 `STORY / STORYBOARD / PROMPT` 任务中按需加载，解决四类高风险问题：来源内容被概述代替、对白在下游丢失或改写、视频时间线被压薄、图像与视频提示词混用。

它不取代故事创作、导演判断或 `PROMPT_QUALITY_CORE.md`；它只规定从一个已批准创作层传到下一层时，什么必须完整保留，以及如何用本地工具复核。

## 1. 唯一创作链

叙事项目只允许一条权威链：

`来源/批准故事真值 → 当前剧本版本 → 对白库存 → 当前分镜 → MP → TP → NEP → PP`

- 每一层可以增加属于本层的创作细节，但不能静默改变上游事实、事件顺序、角色关系、说话人、逐字对白、动作结果或已锁定结局。
- 旧聊天总结、旧 Prompt、模型记忆和发布文案不能反向覆盖当前剧本。
- 同一范围有多个版本时，只从当前 Artifact ID、版本和 SHA-256 读取；旧版只能作为审计记录。
- “内容太长”“怕模型不听”“为了省算力”都不是删减授权。容量不足时分段，并传递完整 handoff。

## 2. 来源单元与保真级别

进入剧本复写、分镜或 Prompt 编译前，把当前范围拆成稳定、连续的 `source_units`。最小种类：

- `EVENT`：必须发生的事件、选择、反应、揭示或状态变化；
- `DIALOGUE`：人物实际说出的逐字台词；
- `NARRATION`：来源明确存在的旁白、内心文字或广播；
- `NON_LEXICAL`：叹息、哭声、笑声、喘息等人物非词汇发声；
- `VISUAL_FACT`：必须被画面保留的身份、数量、空间、道具、服装、伤势、光源或世界状态。

每个单元使用一个保真级别：

- `VERBATIM`：逐字保留。人物对白进入分镜和视频 Prompt 前必须使用此级别；正式引文和锁定文字同样适用。
- `SEMANTIC`：允许导演化表达，但事件、主体、顺序、因果、动作结果和可见状态不得变化。
- `OPTIONAL`：只有确实可省略、且不影响当前承诺的装饰单元才可使用；不能把难拍内容降为 OPTIONAL。

原创剧本不是“没有来源”。当前剧本一旦被用户批准或进入分镜，其事件、对白和视觉事实就成为下游来源真值。继续润色必须产生新版本，不能在 Prompt 阶段顺手改剧本。

## 3. 全量交付默认值

默认：

```yaml
compression_authority: NONE
delivery_fidelity: FULL_FIDELITY
omitted_source_unit_ids: []
```

规则：

1. 不设通用 Prompt 目标字数，不以“更短更好”作为优化目标。
2. 删除重复质量词、机器说明或同义句，不等于可以删除剧情、对白或导演控制。
3. 只有已核验入口限制才能使用 `VERIFIED_SURFACE_LIMIT + SEGMENTED_FULL_FIDELITY`；必须保存能力证据并采用分段，不得登记省略项。
4. 只有用户明确要求紧凑版，才能另外生成 `USER_REQUESTED + USER_REQUESTED_COMPACT`；完整 MP/NEP 和默认完整版 PP 仍保留，不覆盖。
5. `OPTIONAL` 也不能在没有相应授权的默认全量版中悄悄消失。

## 4. 剧本完整交接

### 4.1 写作前

- 先锁定事实、角色关系、事件顺序、已有对白、旁白类别和不可妥协项。
- 区分 `SOURCE / USER_APPROVED / PROPOSED_DIRECTOR_INFERENCE`。导演补充只能改变可演方式，不能伪装成来源真相。
- 若用户要求“不要删减”，当前范围必须先做来源清单，再写正文；不能边写边凭记忆判断是否覆盖。

### 4.2 每场最低合同

每场剧本至少明确：

- 场景 ID、时间/空间和可见入口状态；
- 当前人物分别想取得什么；
- 冲突或阻力如何实际出现；
- 按顺序发生的可观察动作、选择与反应；
- 每一轮人物发声及其来源单元；
- 场景离开时已经改变的关系、信息或物理状态；
- 下一场必须继承的动作、道具、声场或情绪余势。

来源事件不能只出现在场景摘要里。它必须落入一个可演节拍，并形成可见动作、反应、结果或明确声音事件。多个动作、多人多轮对白、时间跃迁或地点变化应拆为场景/镜头序列，不能靠一个加长段落吞并。

### 4.3 对白

- 对白库存保存稳定 ID、说话人、逐字文本、语言、当前剧本版本和下游镜头归属。
- 同一句进入分镜和 Prompt 时，正文按顺序拼接必须逐字等于库存，不得删字、同义改写、换人或调序。
- 叙述、屏幕文字、环境声和人物非词汇发声不得冒充对白；人物“嗯、啊、呵”等必须保留人物归属和表演语境。
- 新增台词、把叙述改为旁白、把内心文字说出口，必须先标为提议并获得相应授权。
- 对白写作同时确定说话目的、对象、是否打断/停顿/回避、可见反应和句后关系变化；这些是导演信息，不得把逐字文本改成括号里的情绪标签。

### 4.4 剧本回读

依次检查：

1. 来源单元覆盖；
2. 事件与发声顺序；
3. 逐字对白、说话人和发声种类；
4. 场景入口/出口与相邻场继承；
5. 可演性、因果与反应；
6. 自然中文、角色声线和重复节奏。

不要先为了“更有网感”重写对白，再回头补来源；先保真，后做最小范围的授权修订。

## 5. 从剧本到分镜

- 每个镜头回链本镜承担的 `source_unit_ids`；当前分镜范围的并集必须覆盖所有必保单元。
- 一项来源事件可以拆到多个镜头，但不能因拆镜重复对白、提前结果或改变动作方向。
- 对白说不完时使用 `SPLIT_REQUIRED`；跨镜使用 `ONSCREEN_LIP / L_CUT / VOICE_OVER / AUDIO_POST_REQUIRED`，拼接后仍逐字一致。
- 听者反应、动作余势、环境响应和镜头出口必须得到自己的时间，不得为了把完整对白塞进短时长而让角色高速念完。
- 先为整句建立连续声音，再决定有意义的画面边界；标点只提供候选节拍。每次切镜必须承担听者反应、道具或证据状态、空间信息、权力变化或动作后果，同一句不能因切镜重新起句。
- 每对相邻镜头建立交接行，写清上一镜交出的动作、位置、视线、道具、遮挡、构图或声音线索，以及下一镜如何接收；没有具体接力的“自然衔接”不构成交接。
- 分镜修改时长、拆分、顺序或对白后，旧 Prompt、字幕 cue 和 TTS coverage 立即失效。

## 6. 各类 Prompt 的完整性

### 6.1 资产与静态图像

`ASSET_REFERENCE / SHOT_KEYFRAME / SHOT_START_FRAME / SHOT_END_FRAME / SHOT_COMPOSITE_LAYER` 只写单帧可见状态。按任务保留：

- 主体身份、数量、几何、服装、道具归属和锁定特征；
- 参考图分别控制和不得控制的内容；
- 构图、景别、机位、轴线、前中后景和安全区；
- 姿态、重心、接触点、表情和视线；
- 材质、固定光源、遮挡、反射、阴影和环境介质；
- 当前风险对应的精简负向约束。

静态图 Prompt 不写秒数、运镜、连续动作、对白音轨或“先……然后……”。若需要动作过程，改用 `ASSET_MOTION_REFERENCE / SHOT_MOTION`。

### 6.2 视频 Prompt

最终视频 PP 默认保留六个可复制 section：

1. `TASK`：自然时长/画幅或继承方式、核心事件、可见结局；
2. `REFERENCE_ASSET`：输入职责、身份、数量、服装、道具和关键几何；
3. `SCENE_STYLE_CONTINUITY`：空间、光源、环境介质、入口连续性与被批准的媒介风格；
4. `DIRECTOR_TIMELINE`：连续覆盖 0 到自然时长的全部节拍；
5. `SOUND`：跨片声场、语言、声线、音乐/环境和原生音频或后期责任；
6. `NEGATIVE`：只阻止当前已识别风险，不写第二套剧情。

每个视频节拍必须实质包含：

- 时间范围和入口状态；
- 景别/机位/构图目的、一个主要运镜家族和本拍结束位置；
- 可观察动作的准备、执行、接触/释放、反作用、制动或余势及终态；
- 当前景别能读到的视线、呼吸、姿态、手势、微表情或反应延迟；
- 接触点、材质受力、光影、天气/介质或 VFX 的因果响应；
- 本拍真实对白、人物非词汇发声、环境声和声音责任；
- 下一拍必须继承的可见出口。

每项输入参考还要明确一个主要职责和禁止带入项。人物或产品标准参考控制不可变身份；动作/摄影参考只控制被批准的运动或摄影，不得覆盖身份、服装、环境、标识和当前连续性。上一支素材被用户接受后，它观察到的真实末态覆盖计划入口；被拒绝素材不进入后续 Prompt。

“电影感、自然运动、情绪饱满、保持一致、动作流畅”只能作为方向，不能代替上述可观察内容。

### 6.3 纪实真实感与拍摄来源

只有用户目标包含手机随拍、家庭录像、DV、监控、纪录片或其他明确素材来源身份时，才额外锁定：谁在拍、使用什么设备/年代、为什么拍、设备会产生哪些可观察操作与成像特征。物理缺陷应与设备一致，例如对焦搜索、曝光波动、滚动快门、压缩伪影或固定高位机位；不要把一套“去 AI 缺陷包”套在所有商业片、动画或神话视觉上。

真实感来自可解释的几何、材质、光、接触、惯性、声源和时间变化，不来自“8K、极致、大片感、顶级质感”等空泛质量词。

### 6.4 对话视频

- 逐字台词只在它实际发生的时间段出现一次，不再附一份“完整对白清单”。
- 每段明确说话人、语言、声线/气息/音量趋势、停顿和交接；说话时谁可见、谁负责口型、谁只听和如何反应必须清楚。
- 切到听者、道具或环境时使用 L-cut，画外声音继续，但画面中的听者不得同步开口。
- 目标模型不支持音频时仍保留逐字台词、时间点、说话人和同步责任，并标记 `AUDIO_POST_REQUIRED`；不能把不支持音频理解成可以删对白。
- 对话占满时长时优先拆镜或延长经批准的编辑时长，不强制角色不自然高速说话。

## 7. Master 本地创作预检

对以下范围准备预检 JSON，并只通过包根目录运行 `运行银幕总控.cmd 创作预检 <创作预检.json> --output <机器报告.json>`：

- 第一个完整剧本样场；
- Prompt Pilot 中的每个高风险对话视频；
- 第一个静态图 Prompt；
- 任何发生删减授权、分段、对白修改、说话人修改或时间线重排的范围；
- 最终批次至少抽查一个普通目标。

工具接收 JSON，不覆盖源文件。共同顶层字段：

```json
{
  "contract_version": "alpha7-master-creative-preflight-v1",
  "mode": "SCRIPT | VIDEO_PROMPT | IMAGE_PROMPT",
  "source_units": [],
  "compression_authority": "NONE",
  "delivery_fidelity": "FULL_FIDELITY",
  "authority_refs": [],
  "omitted_source_unit_ids": []
}
```

- `SCRIPT` 增加 `script.scenes[]`，每场提供入口、目的、冲突、节拍、逐条发声和出口。
- `VIDEO_PROMPT` 增加 `video_prompt`，包含六个 sections、唯一 `prompt_text`、自然时长、连续 beats 和 `audio_responsibility`。
- `IMAGE_PROMPT` 增加 `image_prompt`，包含五个静态 sections、唯一 `prompt_text` 和逐来源锚。

发布构建会独立执行工具自测；普通创作不需要直接调用底层 Python。创作预检退出码 0 只表示本次结构和保真检查通过；退出码 2 表示存在明确缺口。完整错误留在机器附件，普通用户只看到自然中文说明和最低成本修复。

## 8. 完成边界

Master 创作预检通过可以证明：当前声明范围没有被工具检测到来源漏项、逐字对白变化、说话人/顺序漂移、时间线断裂、静态/视频混用或未授权压缩。

它不能证明：剧本一定精彩、对白一定自然、Prompt 一定被模型服从、口型一定准确、真实视频已经生成或媒体质量已经通过。没有真实生成媒体时，Production Validation 仍为 `NOT_TESTED`。
