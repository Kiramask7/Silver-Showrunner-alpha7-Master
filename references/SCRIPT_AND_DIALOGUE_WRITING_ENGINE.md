# Alpha.7 Master 剧本与对白创作引擎

本文件只在撰写或修订剧情场景、人物对白、剧情旁白或口播时加载。它负责创作质量和自然语言；来源覆盖、逐字对白与下游交接另按 `ALPHA7_CONTINUUM_CREATIVE_FIDELITY_ENGINE.md` 执行。

它不替代事实保护、长篇来源冻结、分镜、Prompt 质量核心或中文终检。

## 1. 先判断本轮在做什么

- `ORIGINAL_WRITING`：从已批准前提、人物和节拍创作新剧本；
- `SOURCE_ADAPTATION`：把原作、资料或旧剧本转换为当前形式；
- `LOCKED_REVISION`：只修订用户点名范围，其余台词、事实、顺序和因果保持不动；
- `SCENE_EXPANSION`：把已批准节拍展开成可演场景；
- `DIALOGUE_POLISH`：只处理角色说话方式，不顺手改事件；
- `NARRATION_OR_VOICEOVER`：只在用户要求或来源本来存在时使用；
- `SCRIPT_REVIEW_ONLY`：只诊断和建议，不直接重写。

用户要求“保留原文、不要缩减、只改对白、不要旁白”等约束优先于通用工艺。审阅请求不自动授权改稿。

## 2. 适用边界

- 剧情、人物冲突、情感变化和对白场景：适用。
- 纪录片、科普、教程、专业材料：事实、证据和受众理解优先，不套用剧情反转和潜台词。
- 纯视觉、无对白动作或环境叙事：不强制对白、内心独白或旁白。
- 用户逐字原文、正式引用、数据、已批准剧情和锁定台词：不得为了文风而改写。
- `TEXT_ONLY_ECO_TEST` 使用自包含合同，不额外加载本文件。

## 3. 写作前冻结

先锁定：

1. 人名、身份、关系、地点、时间、数字、引文和世界规则；
2. 已确认因果、事件顺序、进入状态和离开状态；
3. 必须逐字保留的对白、旁白和人物发声；
4. 用户明确禁止的内容、口吻和改写范围；
5. `SOURCE / USER_APPROVED / PROPOSED_DIRECTOR_INFERENCE` 的边界。

只有用户提供或明确授权的样稿，才能用来建立项目声线。没有样稿时只做通用清晰化，不声称复制了用户个人风格。

## 4. 从节拍到完整场景

每场先回答七个问题：

1. 人物进入时的物理、信息和关系状态是什么？
2. 场内主导人物现在具体想让谁做什么、相信什么或停止什么？
3. 阻力如何在动作、资源、信息、时间或关系中真实出现？
4. 哪个选择、失误、发现或代价让局势发生变化？
5. 对白如何改变行动和关系，而不只是解释背景？
6. 观众能看见或听见什么，证明变化已经发生？
7. 场景结束后，下一场必须继承什么？

然后按需要组织：

`入口动作 → 尝试 → 阻力/回应 → 升级 → 选择或揭示 → 直接反应 → 可见出口`

这不是固定七拍模板。短场可以合并，长场可以循环，但不能只留下开场和结论，把冲突过程压成一句概述。

## 5. 动作必须可演

- 把“紧张、愤怒、释然、心虚”翻译成当前景别能读到的视线、呼吸、姿态、重心、手部、停顿、音量变化或对环境的处理。
- 动作需要准备、执行、接触/释放、反作用和结果时，不要只写动作名称。
- 环境细节只在能证明人物状态、空间关系、年代、因果或转折时进入正文；不要为了“写厚”堆气味、温度和光影。
- 一句动作若同时跨越多个位置、时间、目标或结果，拆成顺序清楚的动作链。
- 关键动作发生后给人物和环境直接反应，避免事件刚发生就跳到下一条信息。

## 6. 人物对白

### 6.1 每轮对白的功能

写台词前先确定说话人此刻想：

- 获取信息；
- 隐瞒或转移；
- 迫使对方选择；
- 争夺定义权；
- 维持体面或关系；
- 试探边界；
- 拒绝、安抚、威胁、求助或结束谈话。

台词是否直说、回避、打断、答非所问、沉默或重复对方关键词，由人物目标和关系决定。潜台词是可选手段，不是每句强制藏话。

### 6.2 区分人物声线

人物差异来自稳定选择，而不是给每个人贴一个口头禅：

- 句子长短和完整程度；
- 更常先说事实、感受、命令、问题还是判断；
- 对谁使用称呼、敬语、省略和打断；
- 压力下是变快、变慢、重复、沉默还是转移；
- 哪些内容不愿直接说；
- 说完后是否等待、回避目光、继续动作或立刻补救。

不要让所有人物都使用作者同一种排比、总结、金句和“正确表达”。

### 6.3 对话轮次

- 一轮对话至少产生一个变化：信息增减、关系升降、行动改变、误解加深或风险显形。
- 问答不必机械对应，但答非所问必须有明确人物目的或压力依据。
- 打断要明确谁打断、发生在哪个词或动作点、被截断信息是否在后面回收。
- 停顿、沉默和非词汇发声必须有可演作用；不能用满篇省略号代替表演。
- 说话人开口时，听者仍在行动和反应；不要让其他人物进入静止等待状态。
- 多人场景保持说话对象、视线、空间位置和话语权变化清楚。

### 6.4 逐字保护

- 已锁定台词只调整表演、调度、镜头和声音责任，不改文字。
- 来源对白进入下游后按库存逐字重构；不能把长句缩成意思相近的短句。
- 人物非词汇发声保留人物归属、顺序和情绪语境。
- 叙述、屏幕文字和环境声不转换成角色台词。
- 需要替换、合并或新加一句时，先交付“原句—建议句—影响范围”，等待授权后建立新剧本版本。

## 7. 旁白、内心与口播

- 旁白优先承担画面无法直接表达的时间跨度、背景因果、数据、观点或叙述视角，不重复描述正在发生的动作。
- 内心文字只有在作品形式已批准时使用；不能把所有情绪都说出来，抹掉表演空间。
- 口播先保证信息和说话目的清楚，再处理节奏；不要把标题式短句机械堆成“有力量”的朗诵。
- 画面已经承担信息时，让声音提供新的关系、因果、评价或反差；声音没有新增价值时可以不说。

## 8. 注意力与节奏

注意力不是每几秒强行反转。检查：

- 开场是否给出具体观看任务，而不是空泛悬念；
- 观众是否知道当下谁想要什么；
- 每次升级是否改变风险、选择、信息或关系；
- 承诺是否在当前作品范围内得到兑现；
- 解释后是否给反应和理解空间；
- 钩子是否来自真实未解决问题，而不是故意藏掉本该告诉观众的信息。

平台证据可以调整节奏，但不能在没有批准时改写核心故事、删对白或压缩因果过程。

## 9. 长短篇差异

### 短剧、漫剧与叙事短片

- 优先建立单场目的、可见冲突、清楚出口和下一段钩子；
- 短不等于只留金句；动作、反应和对白交接仍须完整；
- 一镜承载不了多轮对话时拆镜，不把所有内容塞成高速口播。

### 长篇与系列

- 先冻结全局来源、人物/世界规则、信息释放和连续性，再做当前批次；
- 当前场只加载需要的 Bible 切片和相邻 handoff，不用聊天记忆补全；
- 延迟兑现必须登记回收点，不能变成无限拖延；
- 同一角色跨集声线变化必须来自弧光、关系或状态变化，不是随机改写。

## 10. 自然中文回读

以下只是修订信号，不是词语黑名单：

- 多段使用相同开头、排比和总结句；
- 角色轮流说出完整观点，没有真实回应或回避；
- 形容词声称情绪，却没有动作、语气、空间或后果支撑；
- “他沉默了”“空气凝固了”等泛化句在短距离重复；
- 每场结尾都用一句升华或金句；
- 修订后更花哨，却丢失了事实、人物目的或可演信息。

发现问题时，只修改最小受影响范围。普通词出现一次不构成退回理由；更不能为了规避检测而把自然中文改得别扭。

## 11. 剧本交付格式

普通用户优先看到可直接审阅的剧本正文。需要制作交接时，每场保留：

- 场次、时间、地点、内外景；
- 当前出场人物；
- 可演动作与人物反应；
- 说话人明确的逐轮对白；
- 必要声音、画面文字或旁白类别；
- 场景出口和连续性承接。

内部来源 ID、覆盖表、差异和预检报告进入附件。用户没有要求工程信息时，不把正文夹在状态码和 JSON 之间。

## 12. 完成检查

交付前确认：

- 当前范围的来源事件、视觉事实和发声是否完整；
- 对白是否逐字、说话人正确、顺序不变；
- 每场是否有入口、目的、阻力、变化、反应和出口；
- 人物行动与声线是否来自角色而非通用模板；
- 是否擅自新增旁白、内心、台词、因果或事实；
- 是否把长场景压成摘要，或把短场景用无关细节灌长；
- 修订是否只触及被授权范围；
- 需要进入分镜/Prompt 的样场是否已通过 Master 本地创作预检。

本引擎是创作指导，不是独立审美评分器。本地预检通过不等于剧本质量已获独立编辑认可，更不等于真实媒体生成通过。

本模块受若干开源写作工具的一般工艺思路启发，正文为银幕总控独立重写；项目、许可与未吸收边界见 `THIRD_PARTY_ATTRIBUTIONS.md`。
